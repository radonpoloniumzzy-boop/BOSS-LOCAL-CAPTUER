# 招聘人才工作台 UI 参考设计改造报告

## 1. 报告摘要

本轮改造在不扩展招聘业务功能、不修改数据库和本地接口的前提下，重新设计了本地网页工作台的应用壳层、首次启动页、视觉令牌和基础动效。

设计没有采用自由发挥路线，而是明确参考以下三个项目：

- Open Design：<https://github.com/nexu-io/open-design>
- Design OS：<https://github.com/buildermethods/design-os>
- React Bits：<https://github.com/DavidHDev/react-bits>

改造结果已经提交到分支 `codex/web-phase-1-foundation`，对应提交为：

```text
9da4737 feat: align workbench with reference design systems
```

## 2. 改造目标

本轮主要解决以下体验问题：

1. 原深色侧栏固定占用 224px，分屏使用时内容区域过窄。
2. 首次启动页视觉面积过重，深绿色块与业务工作台气质不够统一。
3. 页面样式缺少可追溯的设计契约，后续页面容易各自发挥。
4. 工作台缺少精细状态反馈，但又不适合加入高噪声动画。
5. 设置入口在窄窗口中需要保持稳定、直接可达。

最终目标是形成一个适合招聘运营工作的安静、精确、可信、可重复使用的本地工作台。

## 3. 参考项目采用情况

### 3.1 Open Design

采用内容：

- 使用 `DESIGN.md` 作为项目设计约束的单一事实来源。
- 使用语义令牌管理画布、表面、文本、边框、操作色、状态色、间距、圆角和动效。
- 参考 `design-systems/application` 的浅色专业应用令牌结构。
- 记录设计来源、许可证和项目级覆盖项。

本项目覆盖项：

- 字间距始终为 `0`。
- 卡片和控件圆角不超过 `8px`。
- 工作台保持浅色优先。
- 不使用装饰性紫色、渐变背景和大面积阴影。

### 3.2 Design OS

采用内容：

- 使用紧凑、固定的应用顶栏承载产品身份和运行状态。
- 使用第二层横向流程导航表达产品功能分区。
- 当前、待开发和固定工具入口拥有明确状态。
- 页面内容使用受约束的最大宽度和响应式边距。
- 设置从流程导航中分离，固定为右上角工具按钮。

实际收益：

- 取消永久侧栏后，分屏窗口的有效内容宽度明显增加。
- 900px 窗口下设置入口仍然始终可见。
- 招聘流程导航在空间不足时只在自身内部横向滚动，不导致整个页面溢出。

### 3.3 React Bits

采用内容：

- 参考 CountUp 的数字变化表达方式，用于候选人数、采集批次和最新批次。
- 数字只在数据加载后播放一次，最长约 700ms。
- 动效只负责表达“数据已经载入”，不承担装饰功能。

实现方式：

- 没有安装 React Bits、GSAP 或 Motion 运行时。
- 使用项目内 TypeScript 轻量实现，避免增加明显构建体积。
- 当动画帧被浏览器节流时，通过定时兜底保证最终数字一定正确。
- 开启 `prefers-reduced-motion` 后直接显示最终值。

明确拒绝：

- 粒子、光束、动态背景和鼠标跟随效果。
- 模糊入场、弹跳卡片和持续循环动画。
- 与招聘信息阅读无关的炫技交互。

## 4. 视觉系统

### 4.1 核心颜色

| 角色 | 颜色 | 用途 |
|---|---|---|
| 页面画布 | `#f6f7f9` | 工作台背景 |
| 主表面 | `#ffffff` | 卡片、输入框、设置区域 |
| 信息表面 | `#eef4ff` | 运行说明和轻提示 |
| 主文本 | `#172033` | 标题和主要数据 |
| 次级文本 | `#3b4658` | 描述信息 |
| 弱化文本 | `#6b7689` | 元数据和辅助标签 |
| 操作蓝 | `#2563eb` | 当前选择、焦点和主操作 |
| 成功绿 | `#16a34a` | 服务正常、数据库就绪 |
| 危险红 | `#dc2626` | 错误状态 |

蓝色只负责交互，绿色只负责运行状态，避免页面被单一色系支配。

### 4.2 字体与密度

- 字体优先级：Inter、Segoe UI、Microsoft YaHei、系统字体。
- 工作字号：12、14、16、18、22、30px。
- 工作台页面标题最大 30px。
- 字间距统一为 0。
- 使用 8px 间距节奏，必要时使用 4px 光学调整。

### 4.3 组件规则

- 圆角只使用 4、6、8px。
- 页面分区优先通过留白和边框表达，不把所有内容包装成卡片。
- 指标数据允许使用三个独立卡片。
- 熟悉的工具操作使用 Lucide 图标，例如设置齿轮。
- 所有输入保留可见标签、焦点状态和稳定错误区域。

## 5. 页面结构变化

### 5.1 工作台壳层

改造前：

```text
224px 深色侧栏 + 顶部状态栏 + 主内容区
```

改造后：

```text
第一层：品牌 / 本地服务状态 / 版本 / 设置
第二层：招聘流程导航
第三层：当前页面内容
```

流程导航包含：

```text
概览 → 采集批次 → 候选人 → 岗位 → AI 分析 → 人工复核 → Mapping 与报告
```

阶段 1 尚未完成的业务入口继续显示为待开发和禁用状态。

### 5.2 首次启动页

- 从大面积深色左右分屏改为浅色、低噪声双栏。
- 左侧保留本地数据和隐私说明。
- 右侧集中处理数据目录选择、现有数据库识别和确认操作。
- 390px 窄屏下自动变为单列，主要按钮仍可在首屏看到。

### 5.3 设置入口

- 设置不再跟随流程导航滚动。
- 右上角固定使用 32×32px 齿轮按钮。
- 提供 `aria-label` 和原生悬停提示。
- 900px 分屏测试中可以直接进入“本地配置”。

## 6. 动效边界

允许：

- 控件状态反馈：140ms。
- 页面和区域进入：220ms。
- 指标数字加载：最长约 700ms，只运行一次。

禁止：

- 永久循环的非必要动画。
- 动态装饰背景。
- 大距离位移和明显弹跳。
- 依赖动画才能理解的状态信息。

降级规则：

```css
@media (prefers-reduced-motion: reduce)
```

开启减少动态效果后，非必要动画时间被压缩，数字直接显示最终值，功能和信息保持完整。

## 7. 技术实现

主要文件：

| 文件 | 作用 |
|---|---|
| `DESIGN.md` | 项目设计契约、来源和禁止项 |
| `web/frontend/src/design-tokens.css` | 语义颜色、字体、间距、圆角和动效令牌 |
| `web/frontend/src/App.tsx` | 新应用壳层、流程导航和设置入口 |
| `web/frontend/src/styles.css` | 响应式布局和组件样式 |
| `web/frontend/src/components/CountUp.tsx` | 轻量数字动效 |
| `web/frontend/src/components/CountUp.test.tsx` | 动效降级和节流兜底测试 |
| `web/frontend/src/App.test.tsx` | 导航结构和固定设置入口测试 |

本轮没有修改：

- FastAPI 接口。
- SQLite 数据库及迁移版本。
- Chrome 扩展。
- 旧 PySide 桌面程序业务功能。

## 9. 当前结论

本轮已经完成应用基础壳层的设计定标，可以作为后续候选人库、岗位、AI 筛选、人工复核和报告页面的统一视觉基础。

后续新增页面必须继续遵守根目录 `DESIGN.md`，优先复用现有令牌、导航和反馈模式。除非重新完成设计评审，不应引入第二套颜色、圆角、卡片系统或动画语言。
