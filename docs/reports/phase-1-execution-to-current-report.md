## 2. 执行摘要

本阶段在不替换现有 PySide 桌面端、不修改 Chrome 扩展采集链路的前提下，为项目建立了一个可独立启动的本地网页工作台基础。

3. 首次启动和数据目录确认。
4. 对现有 SQLite 人才库的安全读取。
5. 网页端与桌面端共享的数据库单实例锁。
6. 数据库迁移前自动备份基础。
7. 稳定、中文化的本地接口错误协议。
8. 基于 Open Design、Design OS 和 React Bits 的 UI 设计定标。
9. 桌面、分屏和移动尺寸的真实浏览器验收。

阶段 1 已达到“安全启动、识别旧库、显示真实状态、不会与旧桌面端并发写库”的目标。招聘业务页面尚未迁移到网页端，这是当前边界，不是遗漏。

## 3. 原始目标与边界

阶段 1 的核心目标是建立本地网页基础和安全迁移入口：

- 网页服务只允许本机访问。
- 首次启动只确认数据目录，不自动搬迁旧数据。
- 继续读取原有候选人、批次和配置。
- 网页端与旧桌面端不能同时使用同一数据库。
- 数据库升级前必须先备份，备份失败则停止升级。
- 旧 PySide 页面和 Chrome 扩展继续正常工作。
- 本阶段不迁移候选人列表、岗位、AI 筛选、人工复核和报告页面。

该边界已经通过规格文件和架构决策记录固化：

- `docs/specs/local-web-phase-1-foundation.md`
- `docs/adr/0004-local-web-transition-architecture.md`

## 4. 架构实现

### 4.1 双入口过渡架构

当前项目保留两个独立入口：

```text
app.py
└─ 现有 PySide 桌面端
   └─ Chrome 扩展接口：http://127.0.0.1:17863

web_app.py
└─ 新本地网页工作台
   └─ FastAPI + React：http://127.0.0.1:17864
```

两个入口可以读取同一数据目录，但不能同时持有同一个数据库锁。

### 4.2 网页后台

新增 FastAPI 服务负责：

- 启动健康检查。
- 首次设置状态。
- 数据目录确认和校验。
- 数据库连接与统计读取。
- 提供生产构建后的 React 静态文件。
- 将内部错误转换为稳定的中文 JSON 错误。

服务只绑定：

```text
127.0.0.1:17864
```

同时限制 Host 和 Origin，默认不允许局域网或公网访问。

### 4.3 网页前端

前端采用：

```text
React 19
TypeScript
Vite
Lucide React
Vitest + Testing Library
```

生产构建由 FastAPI 本地提供，不依赖 CDN，也不会在运行时下载界面资源。

## 5. 首次启动与数据目录

首次启动配置保存于：

```text
%LOCALAPPDATA%\RecruitingTalentWorkbench\bootstrap.json
```

只保存：

- `data_dir`
- `web_port`
- `setup_completed`
- `app_version`

不会保存：

- 候选人数据
- AI Key
- Chrome 扩展 Token
- 简历内容

数据目录校验会拒绝：

- 磁盘根目录。
- Windows 系统目录。
- 项目源码根目录。
- 不可写目录。
- 无法识别的非空目录。
- 损坏或缺少必要表的伪数据库。

若项目现有 `data/boss_local_tool.db` 可用，工作台会推荐原数据目录并继续读取，不移动数据、不覆盖 `config.json`。

## 6. 数据安全与单实例

### 6.1 数据库锁

数据库锁身份根据数据库绝对路径生成。

Windows 使用命名互斥量，保证：

- 桌面端和网页端不能同时打开同一数据库。
- 两个网页实例不能同时打开同一数据库。
- 一个实例异常退出后，操作系统能够回收锁。
- 锁不会因残留诊断文件形成永久死锁。

冲突时程序显示中文提示，不会静默继续运行。

### 6.2 数据库备份

数据库仅在 schema 版本低于当前版本时执行迁移前备份。

备份规则：

- 使用 SQLite 一致性备份。
- 文件名包含原版本和唯一时间戳。
- 备份成功后才允许迁移。
- 备份失败立即停止，不修改原数据库。

阶段 1 没有新增 schema，数据库版本仍为 `16`，因此正常启动不会反复生成无意义备份。

## 7. 本地接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 检查网页服务是否启动，不依赖数据库 |
| GET | `/api/setup/status` | 返回首次设置状态、建议目录和旧库识别结果 |
| POST | `/api/setup` | 确认唯一数据目录，只允许成功一次 |
| GET | `/api/app/status` | 返回数据库状态、候选人数和采集批次统计 |

接口统一返回结构化错误：

```json
{
  "error": {
    "code": "database_not_ready",
    "message": "数据库尚未就绪。"
  }
}
```

HTTP、数据库初始化、目录校验和未知异常均不会直接导致网页或 Python 进程无提示退出。

## 8. 运行问题与修复记录

### 8.1 `Failed to fetch`

首次视觉测试期间，测试用网页服务已经停止，但浏览器页面仍然打开。点击“确认并开始使用”时，浏览器显示原始错误：

```text
Failed to fetch
```

该问题并非数据库损坏，而是前端没有把网络断开转换为用户可理解的信息。

修复后提示为：

```text
无法连接本地服务，请确认网页程序仍在运行。
```

并增加了“首次设置提交过程中服务断开”的自动测试，避免原始浏览器错误再次直接暴露。

### 8.2 并发首次设置

审查发现两个首次设置请求可能同时进入。现已通过运行时可重入锁串行化设置流程，确保只有一个请求能够完成并持有最终数据库锁。

### 8.3 损坏数据库影响健康检查

原实现中，已配置数据库初始化失败可能阻止整个网页服务启动。修复后：

- `/api/health` 仍可返回服务状态。
- `/api/app/status` 返回 `database_not_ready`。
- 用户可以看到数据库问题，而不是得到无法区分的连接失败。

### 8.4 数据库连接释放

补齐了 schema 检查异常时的连接关闭路径，避免初始化失败后残留 SQLite 连接。

### 8.5 构建残留

TypeScript 最初会把 `vite.config.js`、声明文件和 `*.tsbuildinfo` 生成到源码目录。现已调整 TypeScript 配置，构建缓存进入 `node_modules/.tmp`，源码目录保持干净。

## 9. UI 设计定标

阶段 1 基础功能完成后，原页面仍存在侧栏占宽、分屏效率低、首次启动页视觉过重等问题。随后完成了第二轮 UI 定标。

设计参考被明确锁定为：

- Open Design：设计契约和语义令牌。
- Design OS：紧凑应用壳层和流程导航。
- React Bits：克制的状态动效模式。

项目根目录新增：

```text
DESIGN.md
```

该文件成为后续网页页面的设计单一事实来源。

### 9.1 工作台壳层变化

改造前：

```text
224px 深色固定侧栏 + 顶部状态栏 + 内容区
```

改造后：

```text
第一层：品牌 / 本地服务状态 / 版本 / 固定设置入口
第二层：招聘流程导航
第三层：当前工作区内容
```

直接收益：

- 取消永久侧栏，增加分屏有效宽度。
- 900px 窗口下设置入口仍固定可见。
- 流程导航空间不足时只在自身内部横向滚动。
- 页面主体不会产生横向溢出。

### 9.2 首次启动页变化

- 取消大面积深绿色幕墙。
- 改为浅色、低噪声双栏。
- 左侧说明数据与隐私，右侧集中完成目录确认。
- 390px 窄屏自动变为单列。
- 保留明确的错误、成功、加载和禁用状态。

### 9.3 视觉令牌

新增 `web/frontend/src/design-tokens.css`，统一管理：

- 页面画布与表面。
- 主文本、次级文本和弱化文本。
- 操作蓝、成功绿、警告和危险色。
- 4/6/8px 圆角。
- 字号、间距、焦点和动效时长。

明确禁止：

- 装饰性渐变。
- 粒子和动态背景。
- 紫色作为主要装饰色。
- 大面积卡片嵌套。
- 负字间距。
- 与信息读取无关的持续动画。

### 9.4 动效

候选人数、批次数和最新批次使用一次性 CountUp 风格动效。

实现特点：

- 不引入 React Bits、GSAP 或 Motion 运行时。
- 动画最长约 700ms。
- 动画帧被浏览器节流时，定时兜底保证最终数字正确。
- `prefers-reduced-motion` 开启时立即显示最终值。
- 页面内容不依赖动画才能理解。

## 14. 风险与注意事项

1. 网页端目前主要验证架构和设计壳层，业务价值仍依赖后续页面迁移。
2. 插件仍依赖桌面端，因此迁移期存在两个本地端口和两个启动入口。
3. 正式安装包尚未纳入网页前端构建产物，干净环境启动前需要先执行 `npm.cmd run build`。
4. FastAPI TestClient 后续需要跟随依赖升级处理弃用警告。
5. 后续页面必须遵守根目录 `DESIGN.md`，否则容易重新出现不同颜色、圆角和动效体系。

## 15. 总结

从阶段 1 启动到当前，项目已经从“只有旧桌面界面的招聘采集程序”增加了一套安全、可渐进迁移的本地网页基础。

当前最重要的成果不是首页本身，而是以下四个长期基础：

```text
安全的数据目录与单实例边界
可继续读取原库的 FastAPI 服务
可测试、可构建的 React 工作台
有来源、有规则、可持续扩展的设计契约
```

因此，项目已经具备进入下一阶段业务页面迁移的条件，但尚不能把网页工作台视为旧桌面端的完整替代品。
