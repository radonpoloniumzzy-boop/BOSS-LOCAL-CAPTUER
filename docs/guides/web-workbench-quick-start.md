# 网页工作台快速开始

这份说明只覆盖当前已经稳定可试用的流程：

启动网页工作台
→ 配对 Chrome 插件
→ 可选设置岗位和招聘任务上下文
→ 采集候选人
→ 网页查看候选人、来源历史和批次
→ 导出批次 Markdown

## 第一次安装

1. 安装官方 CPython 3.12。
2. 获取当前 `main` 分支源码。
3. 双击 `setup_web_workbench.cmd`。
4. 看到“初始化完成，请双击 launch_web_workbench.cmd 启动网页工作台。”后，再双击 `launch_web_workbench.cmd`。

## 日常启动

1. 双击 `launch_web_workbench.cmd`。
2. 等待启动窗口完成环境、端口和人才库检查。
3. 浏览器会自动打开网页工作台。

如果启动器提示缺少运行环境，先回到 `setup_web_workbench.cmd`。

## 第一次确认人才库

首次打开网页工作台时，会先确认数据目录。

建议使用：

- 独立、可写、长期保留的本地文件夹；
- 不与项目源码目录混放；
- 不使用随时可能断开的移动盘，除非你明确知道备份和恢复流程。

## 加载 Chrome 插件

1. 打开 `chrome://extensions`
2. 打开“开发者模式”
3. 选择“加载已解压的扩展程序”
4. 选择项目中的：

```text
extension
```

## 配对插件

1. 在网页工作台“设置”页复制一次性连接码。
2. 打开插件弹窗并粘贴连接码。
3. 配对成功后，插件会自动记住当前网页工作台连接。

网页模式下不需要手工填写 API 地址或 Token。

## 安全与隐私边界

- 一次性连接码只用于插件配对，配对成功后失效。
- Token 不需要手工填写，不会进入 URL，也不会显示在网页普通页面、插件状态文案或启动日志里。
- 插件会在本机浏览器保存连接状态，方便下次继续使用；需要更换连接时，回到网页“设置”重新配对或撤销。
- 原始快照是你主动采集后保存的候选人业务内容，只在候选人详情、批次详情和导出等阅读场景中展示。
- 内部字段名例如 `raw_card_text` 只是程序存储用语，普通使用不需要理解它。
- 候选人列表不会展示原始快照和链接字段；来源历史只展示批次、平台、来源岗位、采集时间和入库结果。

## 采集与查看

你现在可以：

- 在“岗位”页建立岗位档案、岗位版本和招聘任务，并把某个可用任务设为插件当前上下文；
- 采集当前已加载内容；
- 自动滚动采集；
- 回到网页查看候选人列表；
- 查看最近采集批次；
- 导出某个批次的 Markdown。

没有设置当前招聘任务时，插件仍会进行无岗位采集。设置任务后，后续 Web 入库会带上该任务对应的岗位和固定岗位版本。

## 岗位页面怎么用

进入“岗位”后，可以：

1. 新建岗位档案，记录岗位标题、部门、地点、JD 和要求。
2. 编辑岗位档案时生成新的岗位版本，旧版本保留为历史记录。
3. 将岗位切换为招聘中、暂停或关闭。
4. 基于招聘中的岗位和指定版本创建招聘任务。
5. 将可用任务设为插件当前上下文。

招聘任务只保存基础上下文，不代表已经进入 AI 初筛、人工复核、沟通或简历流程。

## 候选人页面怎么用

进入“候选人”后，建议按这个顺序试用：

1. 用搜索框输入候选人姓名、来源岗位文字或原始卡片关键词。
2. 使用来源平台筛选，确认平台来源是否正确。
3. 勾选“只看未绑定岗位”，检查无岗位入库候选人。
4. 点击“查看详情”，打开只读详情抽屉。
5. 在详情里检查：
   - 身份摘要；
   - 基础信息；
   - 摘要与安全链接；
   - 来源出现历史；
   - 原始快照预览、展开和复制。
6. 在“来源出现历史”里点击批次 ID，可以跳到对应批次详情。

候选人详情当前只用于阅读，不会修改候选人主档。

## 批次页面怎么用

进入“最近批次”后，可以：

1. 按状态筛选：全部、已完成、部分成功、失败。
2. 使用“只看失败批次”快速定位异常批次。
3. 使用“只看今天”查看本机业务日期内的采集结果。
4. 按来源平台组合筛选。
5. 输入批次 ID 直接打开旧批次，即使它不在当前第一页。
6. 在批次详情中查看该批次的不可变候选人快照。
7. 点击“查看原始快照”，连续查看上一位、下一位。
8. 点击“导出 Markdown”保存该批次。

批次详情和 Markdown 导出都读取当时的批次快照。后续候选人主档变化不会改写旧批次导出内容。

## 插件采集后看不到新批次

先尝试：

1. 确认插件弹窗显示 Web 工作台模式已连接。
2. 在网页“最近批次”点击刷新。
3. 确认筛选条件没有把新批次过滤掉，例如“只看失败”或来源平台筛选。
4. 回到网页“设置”重新复制连接码，并在插件中重新配对。

网页端和旧桌面端不能同时运行。若旧桌面端正在使用人才库，先关闭旧桌面端。

## 常见错误最短恢复办法

### 提示缺少运行环境

先运行：

```text
setup_web_workbench.cmd
```

### 提示旧版网页工作台仍在运行

先关闭旧实例，再点“重新检查”。

### 提示桌面端正在使用人才库

关闭旧桌面端后，再重新启动网页工作台。

### 数据库文件缺失或损坏

不要创建新空库覆盖旧库。先保留故障文件副本，再按备份与恢复说明处理。

### 插件没有连上

回到网页“设置”重新复制连接码，再在插件里重新配对。

### 导出 Markdown 失败

先确认：

- 当前批次确实存在；
- 网页工作台仍在运行；
- 插件或网页没有切换到另一份人才库连接；
- 浏览器没有拦截下载。

如果问题仍存在，保留启动日志和该批次 ID，再重新启动网页工作台复测。
