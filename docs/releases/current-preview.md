## 新用户试用路径

1. 下载 GitHub `main`。
2. 双击 `setup_web_workbench.cmd` 初始化本项目内的运行环境。
3. 双击 `launch_web_workbench.cmd` 启动网页工作台。
4. 首次打开时确认一个长期保留的人才库目录。
5. 在网页“设置”复制一次性连接码。
6. 在 Chrome 加载项目里的 `extension/` 目录。
7. 在插件中粘贴连接码并完成配对。
8. 在招聘平台页面执行采集。
9. 回到网页查看候选人、来源历史、批次详情和 Markdown 导出。

网页模式不要求用户手工填写 API 地址或 Token。

## M1 验收关注点

- 候选人列表 API 只返回列表所需字段，不暴露原始卡片、来源 URL、详情 URL、AI 字段、人工复核字段或状态历史。
- 候选人详情 API 只返回 M1 详情页明确展示的只读字段。
- 来源出现历史来自 `capture_batch_items` 和采集批次，不通过当前候选人主档反推历史。
- 来源历史接口使用轻量候选人存在性查询，不调用旧桌面端重量级详情链路。
- `today_only` 批次筛选在单次请求内共用同一本机业务日期边界。
- Markdown 导出读取 `capture_batch_items` 不可变快照，后续主档变化不会污染旧批次导出。
- 网页和插件 Web 模式共用 `/api/capture-batches/{batch_id}/export.md`。
- Token、连接码和内部鉴权头不会作为用户可见信息暴露；候选人原始快照只在详情、批次阅读和导出场景按用户操作展示。
- Drawer 使用真实模态语义，支持焦点陷阱、Escape 顶层关闭、focusin 守卫、背景滚动锁和隐藏页面清理。
- `npm.cmd run qa:readability` 使用真实浏览器覆盖 `1920x1080`、`1440x900`、`1280x720`、`760x720`，并验证 reduced-motion 与 focus-visible。

## 已知边界

- Chrome 插件仍是招聘平台页面采集入口。
- 网页工作台是当前默认主入口。
- 旧桌面端只作为兼容入口保留。
- 程序不会在数据库缺失时创建空库替代旧库。
- 网页端和旧桌面端不能同时占用同一人才库。

## 关于旧的“紧凑型分屏工作台”Issue

旧 Issue 关注的是桌面端在半屏与紧凑布局下的可用性。

现在主路线已经切到网页工作台，所以它没有完全失效，但优先级和适用面已经被网页路线明显替代：

- 如果目标是当前正式试用版本的日常使用体验，应该优先推进网页工作台；
- 如果目标仍是维护旧桌面兼容入口，那条 Issue 仍有参考价值。
