# 岗位招聘任务与双窗口工作台

## 目标

招聘任务承载一次具体招聘行动。任务固定岗位版本，保存平台、来源页面、候选人目标、评级目标和平台额度，并统一追踪采集批次、AI 初筛运行及导出文件。

## 状态

```text
待启动 → 执行中 → 等待人工 → 执行中
              ├→ 已暂停 → 执行中
              ├→ 已完成
              ├→ 失败 → 执行中
              └→ 已取消
```

已完成和已取消是终态。任务状态不改变岗位状态，也不代替候选人招聘进度。

## 窗口简化

日常主流程只保留两个主要窗口：

1. 招聘平台：负责登录、验证码和平台页面；
2. HR 工作台：负责岗位、任务、采集状态、AI 初筛、人工复核与导出记录。

Chrome 插件仍是平台页面采集桥梁。招聘任务页提供 AUTO、采集当前、自动滚动、暂停和停止按钮，通过本地任务指令控制插件后台；插件弹窗里的原有按钮继续保留，作为并行入口和故障兜底。导出文件可在招聘任务页直接打开，外部 AI 网页由应用内 API 初筛替代。

前端指令必须携带招聘任务 ID。插件领取后只允许使用桌面端当前运行且岗位一致的任务配置，完成或失败后把结果回传工作台。没有明确任务身份时不得猜测或回退到其他当前任务。

## 当前边界

- 已实现一个任务内的采集、筛选和导出追踪；
- 已实现任务暂停、继续、完成、失败和取消的统一状态；
- 已保存查看、打招呼等计划额度，但尚未自动读取平台真实消耗；
- 平台登录、验证码和访问限制仍必须由用户在普通 Chrome 中处理；
- 多任务并发调度、自动触达和团队权限留待后续阶段。
