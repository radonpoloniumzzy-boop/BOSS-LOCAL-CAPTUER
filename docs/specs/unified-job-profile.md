# 统一岗位档案方案

## 目标

岗位档案是一次招聘需求的唯一身份。采集、AI 初筛、人工复核、候选人岗位关系和后续人才 Mapping 不再分别维护岗位名称或筛选方案，而是共同引用同一个岗位档案。

## 档案内容

- 基础信息：岗位名称、部门、招聘负责人、地点、用工类型；
- 招聘目标：目标人数、截止日期、优先级和岗位状态；
- 任职要求：完整 JD、经验要求、学历要求；
- 筛选规则：必须条件、加分项、风险提示、排除项、面试核验和证据策略；
- AI 规则：自动生成或人工维护的初筛提示词；
- 版本信息：当前版本、历史快照、复制来源和更新时间。

## 状态

```text
草稿 → 招聘中 → 已暂停 → 招聘中
  └────────┐    └──────┴────→ 已结束（终态）
           └───────────────→ 已结束（终态）
```

- 草稿：可以编辑，不能进入新采集、筛选或自动化任务；
- 招聘中：可以被所有新任务选择；
- 已暂停：停止新任务，但历史候选人、复核和筛选结果继续保留；
- 已结束：不再执行新任务，历史数据永久保留，且不能重新开启；需要继续招聘时复制为新草稿。

删除不属于正常岗位生命周期。原有“删除筛选方案”行为改为结束岗位，避免级联删除候选人岗位关系和筛选历史。

## 版本规则

每次保存或状态变更产生一个新的不可变岗位版本。新筛选批次记录启动时的岗位版本；岗位后续修改不会改变已完成判断的版本归属。

从旧数据库迁移的筛选批次无法可靠还原当时岗位版本，因此标记为版本 `0`，表示“历史版本未知”，不伪造精确归属。旧筛选档案升级为招聘中岗位，并生成当前内容的首个版本快照。

## 页面行为

1. 左侧“岗位中心”是唯一编辑入口；
2. 用户可以新建、编辑、复制和调整状态；
3. AI 初筛页面只读岗位规则，只负责选择岗位和执行；
4. 仪表盘只列出招聘中岗位，采集批次保存岗位 ID；
5. Chrome 扩展以岗位 ID 关联岗位档案，岗位名称只保留为采集时的来源快照；旧版扩展没有 ID 时才按招聘中的同名岗位兼容关联；
6. 自动化流程只能选择招聘中岗位；岗位暂停或结束时，清空等待队列，并向关联的采集与 AI 筛选发送停止请求；
7. 人工复核和历史结果仍可查看非招聘中岗位。

## 验收标准

1. 旧筛选档案和已有候选人关系无损保留；
2. 新建岗位能保存全部岗位与筛选字段；
3. 更新岗位后当前版本加一，并可查看旧快照；
4. 筛选批次记录启动时的岗位版本；
5. 复制岗位产生独立草稿和版本线；
6. 暂停岗位不再出现在采集、AI 初筛和自动化的新任务选择中；
7. AI 页面不能编辑岗位内容；
8. 采集批次能追溯到岗位 ID；
9. 最小窗口尺寸下页面仍能通过现有滚动区域使用。
10. 已结束岗位不能恢复为招聘中，岗位改名不会导致扩展批次失去岗位归属。
